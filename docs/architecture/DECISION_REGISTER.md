# Decision register

This register tracks six governed choices. A working consensus may constrain P0 without claiming that the implementation already conforms or that formal ratification is complete. Close each item with a canonical ADR or approved design note, reproducible evidence, an owner, and migration impact.

| Decision                 | Options to compare                                                         | Evidence before decision                                                                                                        | Current position                                                                                                                                                                                                                                                             |
| ------------------------ | -------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| React Aria scope         | Native/custom behavior; selected hooks; broader adoption                   | APG behavior matrix, accessibility defect rate, bundle/runtime cost, API escape hatches, vendor license/provenance              | Working candidate: native behavior for simple primitives and selected React Aria hooks for high-risk composite widgets. No vendor API may leak into the public contract. Close only after component-level evidence.                                                          |
| Multi-brand in one DOM   | Scoped theme roots; Shadow DOM where justified; constrained global theme   | Two brands rendered together, portals/overlays, SSR/hydration, CSS leakage, provider updates                                    | Working consensus: CSS custom properties on scoped subtree roots; document-wide mode is optional and is not multi-brand isolation. Resets are scoped and portals inherit an explicit theme container.                                                                        |
| Styling engine ownership | Keep Sass + Panda with one token source; reduce Panda; consolidate later   | CSS size per import, unresolved `--ds-*`, `staticCss: ["*"]` cost, override conflicts, build time                               | Keep both during P0 under one token contract. Benchmark during P0/P2 and decide consolidation in P3; no engine removal is assumed.                                                                                                                                           |
| Public polymorphism      | `as`; `asChild`; restricted combination; none per component                | Ref/typing behavior, semantic markup, event merging, accessibility, single-child failure, consumer examples, provenance/license | `asChild` is the preferred candidate for APIs that require polymorphism. Do not expand dynamic `as` or declare `asChild` final until the evidence and `Slot.tsx` provenance gates pass.                                                                                      |
| Token physical package   | Keep token source within `@scnx/system`; extract an independent package    | Independent consumers, release/version coupling, circularity risk, migration cost                                               | Working consensus: retain two physical packages. Reopen extraction only when an independent consumer and release boundary are demonstrated.                                                                                                                                  |
| CSS delivery             | Explicit shared stylesheet; component CSS subpaths; JS side-effect imports | Packed consumer render, tree shaking, documented import ergonomics, SSR behavior, federation duplication/order                  | Working consensus: export aggregate component CSS plus explicit theme CSS; the composition root imports each once. Component JS has no CSS side-effect import, remotes do not inject duplicates, and portal theme scope is explicit. Close after packed and federated tests. |

Decision reviews must separate source-level proof from producer build proof, packed-package proof, and application-level proof. A packed consumer never runs Panda to make shipped components render. The producer verifies there are no Panda callsites in `@scnx/core-ui` before removing the `../core-ui/src` scan path.

Any numeric budget must state the import path, raw/minified/compressed representation, tool, environment, and incremental consumer scenario. No universal `<2 KB` requirement is accepted without that evidence.

Formal ADR/SAD/STD status remains unchanged until the required edits, remaining principal review, and consolidated approval are complete.

Until those decisions close, the implementation defaults in the [source-of-truth index](../ARCHITECTURE_SOT.md) constrain new work. An open design decision is not permission to claim the corresponding feature is supported.
